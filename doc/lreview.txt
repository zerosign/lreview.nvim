*lreview.txt*   Unified MR/PR Code Review inside Neovim            August 2026

==============================================================================
INTRODUCTION                                                 *lreview-intro*

|lreview.nvim| is a fast, asynchronous code review plugin for Neovim that 
unifies review operations across GitHub, GitLab, and custom code hosts. It 
leverages local SQLite caching for sub-millisecond thread loading and offloads
networking and sync operations to isolated libuv background worker threads.

Main Features:
- Asynchronous worker threads (`uv.new_work`) with MessagePack serialization.
- Centralized debounced Sync Bus (~80ms coalescing) and in-memory diff cache.
- Idempotent submit state machine with `IN_FLIGHT` transient states and atomic
  SQLite transactions.
- Adapter capability system for safe multiplatform feature queries.
- Repo topology-aware materialization (`checkout` vs `worktree`).
- Summary panel with dual view modes (Threads & Files table) and verdict
  short-circuits (`A` to approve, `R` to reject).
- Floating verdict confirmation popup window.

==============================================================================
INSTALLATION                                          *lreview-installation*

Using |lazy.nvim|:
>lua
  require("lazy").setup({
    {
      "zerosign/lreview.nvim",
      dependencies = {
        "kkharji/sqlite.lua", -- SQLite wrapper dependency
      },
      opts = {
        defaults = {
          db_path = vim.fn.stdpath("data") .. "/lreview/lreview.db",
          topology = "simple", -- "simple" | "monorepo-single" | "monorepo-multi"
          db = {
            busy_timeout_ms = 5000,
            keep_days = 30,
            auto_housekeep = true,
          },
          ui = {
            decor = "both",
            float = { width = 0.5, height = 0.6 },
          },
          open = { method = "checkout" },
        },
        ["github\\.com"] = {
          adapter = "github",
          provider = "gh",
          host = "github.com",
        },
        ["gitlab\\.com|gitlab\\..*"] = {
          adapter = "gitlab",
          provider = "glab",
          host = "gitlab.com",
        },
      },
    }
  })
<

CONFIGURATION                                        *lreview-configuration*

The plugin is configured by passing an options table to `setup()`:
>lua
  require("lreview").setup(opts)
<

Global Settings ~
Inside the `defaults` block of your configuration:

  `db_path`           (string)
                      Absolute path to the SQLite cache file.
                      Default: `vim.fn.stdpath("data") .. "/lreview/lreview.db"`

  `topology`          (string)
                      Repository topology classification for branch materialization.
                      Options: `"simple"`, `"monorepo-single"`, `"monorepo-multi"`.
                      Default: `"simple"`

  `db.busy_timeout_ms` (number)
                      SQLite busy lock timeout in milliseconds.
                      Default: `5000`

  `db.keep_days`      (number)
                      Number of days to preserve closed/merged pull requests.
                      Default: `30`

  `db.auto_housekeep` (boolean)
                      Whether to auto-run SQLite database housekeeping on open.
                      Default: `false`

  `ui.decor`          (string)
                      How inline comment indicators are rendered in buffers.
                      Options:
                        "both"         Render both signs and virtual text.
                        "sign"         Render sign column symbols only.
                        "virtual_text" Render virtual text only.
                        "none"         Disable inline annotations.
                      Default: `"both"`

  `ui.float.width`    (number)
                      Width of floating thread panel (percentage of window).
                      Default: `0.5` (50%)

  `ui.float.height`   (number)
                      Height of floating thread panel (percentage of window).
                      Default: `0.6` (60%)

  `open.method`       (string)
                      Action to execute when starting a review branch.
                      Default: `"checkout"`

Per-Domain Configurations ~
Keyed by a pattern (Lua matching) matching the remote repository domain (e.g.
`["gitlab\\.mycompany\\.com"]`). Supports these configuration attributes:

  `adapter`           (string) Platform adapter (`"github"` or `"gitlab"`).
  `provider`          (string) CLI binary command to run (`"gh"` or `"glab"`).
  `host`              (string) API host domain.

USER COMMANDS                                             *lreview-commands*

`:LocalReviewQuery` [<scope>]
                      Lists available MRs/PRs for the current repository.
                      `scope` can be "mine" (default) or "all".

`:LocalReviewDetail` [<ref>]
                      Opens the markdown-formatted detail buffer editor for an
                      MR/PR. Supports direct saves (:w) to update titles and
                      descriptions on the remote platform.

`:LocalReviewStart`
                      Resolves the repository target MR, initializes database
                      schema connection, and triggers an asynchronous pull.

`:LocalReviewCreate`
                      Launches an interactive picker flow to select target branch
                      and template, and inputs a title to create a remote MR/PR.

`:LocalReviewComment`
                      Adds a local draft comment on the current visually
                      selected line range. Requires an active review.

`:LocalReviewSubmit`
                      Launches the floating confirmation popup window to push
                      local draft inline comments and review verdicts.

`:LocalReviewPull`
                      Triggers an asynchronous worker thread pull (`uv.new_work`)
                      to update comments and threads for the active review.

`:LocalReviewClose` [<number>]
                      Closes the MR/PR on the remote platform and updates the
                      local SQLite database state to "closed".

`:LocalReviewApprove` [<number>]
                      Approves the MR/PR on the remote platform and updates the
                      local SQLite database state to "approved".

`:LocalReviewToggle`
                      Toggles inline annotations (signs & virtual text) on or off
                      for the current buffer.

`:LocalReviewHover`
                      Displays the thread detail floating window for the active
                      discussion thread under the cursor line.

`:LocalReviewSummary`
                      Opens the interactive review summary panel. Supports dual
                      view modes (Threads & Files table), jump, resolve, filter,
                      sort, and direct approve/reject short-circuits.

`:LocalReviewNext`
                      Jumps to the next discussion thread in the active buffer.

`:LocalReviewPrev`
                      Jumps to the previous discussion thread in the active buffer.

SUMMARY PANEL KEYBINDINGS                               *lreview-summary-panel*

The summary panel (`:LocalReviewSummary`) provides a dual-view inspection tool:

  `g`                 Toggle View Mode: switches between **Threads** view and
                      **Files** table view.
  `f`                 Toggle Filter: toggles between active/drafts and all threads.
  `S`                 Cycle Sort Mode: cycles sorting in Files view (`path`,
                      `comments`, `additions`, `deletions`).
  `o` / `<CR>`        Jump / Open: opens selected thread or file at cursor.
  `s` / `r`           Resolve / Reopen: toggles thread resolved state.
  `d`                 Delete Draft: deletes local draft thread under cursor.
  `p`                 Push Selected: submits selected thread changes.
  `P`                 Push All: submits all pending review changes.
  `u`                 Pull Updates: triggers background async pull job.
  `A`                 Approve MR: short-circuit to approve active MR.
  `R`                 Reject MR: short-circuit to submit request changes verdict.
  `q`                 Close: closes summary panel window.

==============================================================================
THREAD VIEW KEYBINDINGS                                 *lreview-keybindings*

When viewing discussion threads (`:LocalReviewHover`), Neovim displays all threads
for the active line sequentially in a split buffer:

  `r`                 Reply: opens a reply window for the selected thread.
  `e`                 Edit: edit an existing local draft comment.
  `d`                 Delete: delete a local draft comment/reply.
  `s`                 Resolve/Reopen: toggles the resolved status of the thread.
  `P`                 Submit: push all local review comments.
  `q`                 Close: closes the thread view panel.

ADAPTER CAPABILITY SYSTEM                             *lreview-capabilities*

Each platform adapter declares its feature capabilities in a `capabilities` table:

  `review_verdict`   (boolean) Verdict support (Approve / Request Changes).
  `draft_mr`         (boolean) Draft MR creation support.
  `update_mr`        (boolean) MR title/description edit support.
  `close_mr`         (boolean) MR closure support.
  `approve_mr`       (boolean) Direct MR approval support.
  `list_templates`   (boolean) MR template listing support.
  `inline_comments`  (boolean) Line-level inline comment support.
  `resolve_threads`  (boolean) Thread resolution support.
  `batch_submit`     (boolean) Batch inline review submission support.

Query capability support via:
>lua
  local adapter = require("lreview.adapter")
  local supports = adapter.supports(resolved_ctx, "review_verdict")
<

ASYNC THREAD ARCHITECTURE                             *lreview-async-model*

lreview.nvim offloads background operations to isolated `uv.new_work` worker
threads via `lreview.thread`:

- **Isolated Lua States:** Worker threads run in separate Lua environments.
- **MessagePack Serialization:** Communication across the thread boundary uses
  `vim.mpack.encode` and `vim.mpack.decode`.
- **Fast Event Escapes:** All thread completion callbacks run inside libuv fast
  event context and are wrapped in `vim.schedule` before invoking Neovim API calls.

==============================================================================
CENTRALIZED SYNC BUS & DIFF CACHE                       *lreview-sync-bus*

All propagation across gutter signs, virtual text, and panel redraws is handled
by `lreview.sync`:

- **Debounced Flush:** Action handlers mark buffers dirty via `sync.mark_dirty(buf)`.
  Flush passes coalesce within an ~80ms window using `vim.uv.new_timer()`.
- **In-Memory Diff Cache:** `sync.get_changed_lines(cwd, path)` caches `git diff`
  results per file, rendering gutter decorations in `0.029 ms` per pass (**78.6x faster**).

==============================================================================
SUBMIT STATE MACHINE & ATOMICITY                     *lreview-submit-atomicity*

Pending review changes transition through a state machine:
- `DRAFT` (1): Unpushed local comment.
- `SYNCED` (2): Confirmed on remote forge host.
- `IN_FLIGHT` (4): Transient state while transmitting over network thread.
- `MODIFIED` (8): Locally edited after remote sync.
- `DELETED` (16): Locally soft-deleted pending remote deletion.
- `CONFLICT` (32): Remote collision detected.

Transactions use `storage.with_transaction(fn)` to wrap state updates in explicit
SQLite `BEGIN TRANSACTION` / `COMMIT` / `ROLLBACK` blocks, guaranteeing zero local
corruption on network failures.

==============================================================================
DATABASE ENGINE & CONCURRENCY                         *lreview-database-engine*

lreview.nvim utilizes `kkharji/sqlite.lua` to access SQLite caches.

SQLite Flavors ~
The plugin automatically detects the running Lua environment:
  - If running in LuaJIT (default in Neovim), it dynamically binds directly to
    the system `libsqlite3.so` using FFI for native execution speed.
  - If FFI is unavailable, it gracefully falls back to `lsqlite3`.

WAL Mode & Concurrency ~
SQLite is opened with Write-Ahead Logging (`PRAGMA journal_mode=WAL;`), enabling
concurrent reads and writes between background worker threads and the main Neovim process.

==============================================================================
GARBAGE COLLECTION                                              *lreview-gc*

SQLite garbage collection runs on database initialization when
`db.auto_housekeep` is set to `true`. Old closed or merged MRs beyond `keep_days`
are purged, while all local drafts (`remote_id IS NULL`) are strictly preserved.
