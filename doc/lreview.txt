*lreview.txt*   Unified MR/PR Code Review inside Neovim            August 2026

==============================================================================
INTRODUCTION                                                 *lreview-intro*

|lreview.nvim| is a fast, asynchronous code review plugin for Neovim that 
unifies review operations across GitHub, GitLab, and other code hosts. It 
leverages local SQLite caching for sub-millisecond thread loading and offloads
all remote networking to background asynchronous CLI execution.

Main Features:
- Asynchronous non-blocking background pulls.
- Offline-first cache: loads thread lists instantly via SQLite WAL.
- Soft-deletion: handles deleted remote comments gracefully without breaking
  nested reply threads.
- Auto-Garbage Collection: automatically purges old closed or merged reviews on
  startup, strictly protecting your local drafts.
- Multi-repository awareness: resolves context dynamically, allowing multiple
  forks and project reviews to coexist in the same database without conflicts.

==============================================================================
INSTALLATION                                          *lreview-installation*

Using |lazy.nvim|:
>lua
  require("lazy").setup({
    {
      "zerosign/lreview.nvim",
      dependencies = {
        "kkharji/sqlite.lua", -- SQLite wrapper dependency
      },
      opts = {
        defaults = {
          db_path = vim.fn.stdpath("data") .. "/lreview/lreview.db",
          db = {
            busy_timeout_ms = 5000,
            keep_days = 30,
            auto_housekeep = true,
          },
          ui = {
            decor = "both",
            float = { width = 0.5, height = 0.6 },
          },
          open = { method = "checkout" },
        },
        ["github\\.com"] = {
          adapter = "github",
          provider = "gh",
          host = "github.com",
        },
        ["gitlab\\.com|gitlab\\..*"] = {
          adapter = "gitlab",
          provider = "glab",
          host = "gitlab.com",
        },
      },
    }
  })
<

=============================================================================
CONFIGURATION                                        *lreview-configuration*

The plugin is configured by passing an options table to `setup()`:
>lua
  require("lreview").setup(opts)
<

Global Settings ~
Inside the `defaults` block of your configuration:

  `db_path`           (string)
                      Absolute path to the SQLite cache file.
                      Default: `vim.fn.stdpath("data") .. "/lreview/lreview.db"`

  `db.busy_timeout_ms` (number)
                      SQLite busy lock timeout in milliseconds.
                      Default: `5000`

  `db.keep_days`      (number)
                      Number of days to preserve closed/merged pull requests.
                      Default: `30`

  `db.auto_housekeep` (boolean)
                      Whether to auto-run SQLite database housekeeping on open.
                      Default: `false`

  `ui.decor`          (string)
                      How inline comment indicators are rendered in buffers.
                      Options:
                        "both"         Render both signs and virtual text.
                        "sign"         Render sign column symbols only.
                        "virtual_text" Render virtual text only.
                        "none"         Disable inline annotations.
                      Default: `"both"`

  `ui.float.width`    (number)
                      Width of floating thread panel (percentage of window).
                      Default: `0.5` (50%)

  `ui.float.height`   (number)
                      Height of floating thread panel (percentage of window).
                      Default: `0.6` (60%)

  `open.method`       (string)
                      Action to execute when starting a review branch.
                      Default: `"checkout"`

Per-Domain Configurations ~
Keyed by a pattern (Lua matching) matching the remote repository domain (e.g.
`["gitlab\\.mycompany\\.com"]`). Supports these configuration attributes:

  `adapter`           (string) Platform adapter (`"github"` or `"gitlab"`).
  `provider`          (string) CLI binary command to run (`"gh"` or `"glab"`).
  `host`              (string) API host domain.

USER COMMANDS                                             *lreview-commands*

`:LocalReviewQuery` [<scope>]
                      Lists available MRs/PRs for the current repository.
                      `scope` can be "mine" (default) or "all".

`:LocalReviewDetail` [<ref>]
                      Opens the markdown-formatted detail buffer editor for an
                      MR/PR (defaults to the active review's MR, or checks the
                      current branch). Supports direct saves (:w) to update titles
                      and descriptions on the remote platform.

`:LocalReviewStart`
                      Resolves the repository target MR, initializes database
                      schema connection, and triggers an asynchronous pull.

`:LocalReviewCreate`
                      Launches an interactive picker flow to select target branch
                      and template, and inputs a title to create a remote MR/PR.

`:LocalReviewComment`
                      Adds a local draft comment on the current visually
                      selected line range. Requires an active review.

`:LocalReviewSubmit`
                      Pushes all local draft inline comments as a unified review
                      to the remote platform.

`:LocalReviewPull`
                      Manually triggers an asynchronous remote pull to update
                      comments and threads for the active review.

`:LocalReviewClose` [<number>]
                      Closes the MR/PR on the remote platform. Defaults to
                      the active review's MR.

`:LocalReviewApprove` [<number>]
                      Approves the MR/PR on the remote platform. Defaults to
                      the active review's MR.

`:LocalReviewToggle`
                      Toggles inline annotations (signs & virtual text) on or off
                      for the current buffer.

`:LocalReviewHover`
                      Displays the thread detail floating window for the active
                      discussion thread under the cursor line.

`:LocalReviewSummary`
                      Opens the interactive review summary panel. Lists all active
                      and resolved threads in a split view with options to jump,
                      resolve, sync, delete draft threads, or push changes.

`:LocalReviewNext`
                      Jumps to the next discussion thread in the active buffer
                      and automatically pops open the thread details.

`:LocalReviewPrev`
                      Jumps to the previous discussion thread in the active buffer
                      and automatically pops open the thread details.

==============================================================================
THREAD VIEW & PANEL KEYBINDINGS                         *lreview-keybindings*

When viewing discussion threads, Neovim displays all threads for the active line
sequentially in a split buffer. Key actions are cursor-aware:

  `r`                 Reply: opens a reply window for the selected thread.
  `e`                 Edit: edit an existing local draft comment.
  `d`                 Delete: delete a local draft comment/reply.
  `s`                 Resolve/Reopen: toggles the resolved status of the thread
                      under the cursor.
  `P`                 Submit: push all local review comments.
  `q`                 Close: closes the thread view panel.

CUSTOM ADAPTERS                                            *lreview-custom-adapters*

lreview.nvim supports custom platform adapters (e.g. Gitea, Sourcehut, or internal
code hosts) without editing plugin files. You define a Lua module in your runtime
path (e.g. `lua/my_adapters/gitea.lua`) and specify its path in `opts`.

An adapter module must return a table implementing these standard methods:

  `query(cfg, scope, ctx)`
                      Returns a list of PR/MR model maps.
  `get_mr(cfg, ctx)`
                      Returns detailed metadata for a single PR/MR.
  `fetch_comments(cfg, ctx, last_sync)`
                      Returns list of comments and threads from host.
  `create_comment(cfg, ctx, path, line, body)`
                      Creates a new remote inline comment thread.
  `create_reply(cfg, ctx, reply_to_id, body)`
                      Posts a reply comment on an existing thread.
  `edit_comment(cfg, ctx, remote_comment_id, body)`
                      Edits a remote comment.
  `delete_comment(cfg, ctx, remote_comment_id)`
                      Deletes a remote comment.
  `resolve_thread(cfg, ctx, remote_thread_id, resolved)`
                      Toggles thread resolution state on remote host.

Configure the custom adapter under `opts` using its Lua require module name:

>
  require("lreview").setup({
    ["gitea\\.mycompany\\.com"] = {
      adapter = "my_adapters.gitea", -- Dynamically loaded on remote match
      provider = "gitea-cli",
      host = "gitea.mycompany.com",
    }
  })
<

==============================================================================
ADAPTER RETURN SHAPES                                 *lreview-adapter-shapes*

Custom adapter methods must return Lua tables conforming to these models:

`lreview.MR` (Returned by `query()`)
  - `mo_id`           (string) Unique ID matching "<provider>:<repo>:<number>"
  - `provider`        (string) Forge provider name (e.g. "gitea")
  - `repo`            (string) Repository path, e.g. "owner/repo"
  - `number`          (integer) Merge Request/Pull Request number
  - `title`           (string) Title of the PR/MR
  - `author`          (string) Username of the author
  - `state`           (string) "open", "closed", or "merged"
  - `source_branch`   (string) Source branch name
  - `target_branch`   (string) Target branch name
  - `url`             (string) Web URL of the PR/MR
  - `updated_at`      (string) ISO-8601 timestamp string (e.g. "2026-08-29T12:00:00Z")

`lreview.MRDetail` (Returned by `get_mr()`)
  Extends `lreview.MR` with additional fields:
  - `description`     (string|nil) Description body text
  - `base_sha`        (string|nil) Base merge commit SHA
  - `head_sha`        (string|nil) Head branch commit SHA
  - `files`           (table|nil) Array of file tables. Each file has:
    - `path`          (string) Repo-relative file path
    - `additions`     (integer) Added lines count
    - `deletions`     (integer) Deleted lines count
    - `change_type`   (string) "MODIFIED", "ADDED", or "REMOVED"

`lreview.Comment` (Returned inside `fetch_comments()`)
  - `c_id`            (string) Unique comment ID (matches remote_id on sync)
  - `remote_id`       (string) ID from remote platform
  - `author`          (string) Comment author username
  - `body`            (string) Markdown text of the comment
  - `created_at`      (string) ISO-8601 timestamp string
  - `in_reply_to`     (string|nil) Parent remote comment or discussion ID

`lreview.Thread` (Returned inside `fetch_comments()`)
  - `t_id`            (string) Platform thread/discussion ID
  - `mo_id`           (string) PR/MR unique ID
  - `path`            (string) Repo-relative file path
  - `commit_sha`      (string|nil) Diff commit SHA
  - `start_line`      (integer) Gutter start line (1-indexed)
  - `end_line`        (integer) Gutter end line (1-indexed)
  - `is_draft`        (boolean) True if thread has local drafts
  - `comments`        (table) Array of `lreview.Comment` tables


==============================================================================
GARBAGE COLLECTION                                              *lreview-gc*

SQLite garbage collection runs on database initialization when
`db.auto_housekeep` is set to `true`.

Any PR/MR marked `merged` or `closed` whose last update is older than the
configured `db.keep_days` (default 30 days) is swept from SQLite.

To safeguard your data:
- Draft comments (`remote_id IS NULL`) are NEVER deleted.
- Threads containing unsubmitted drafts are skipped from deletion.
- PRs containing active draft threads are preserved.
